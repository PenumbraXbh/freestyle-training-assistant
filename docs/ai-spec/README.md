# AI 方案摘要

AI 能力分为训练足迹与训练灵感两个独立调用。足迹偏事实整理，必须绑定服务端批准的结论和证据；灵感允许有限创造，但只能从经过筛选的候选主题和变量出发。

## 核心规则

- 未达到 5 条有效记录且 20 个有效信号时，不调用足迹生成模型。
- 达到门槛后，使用最近最多 30 条记录建立统计候选池，最多选择 12 条证据记录进入模型上下文。
- “持续关注”至少需要 3 条相关记录且跨 2 个日期；变化判断至少需要 10 条分析记录，前后各不少于 5 条。
- 主题共同出现或次数变化不能自动推出“从 A 延伸到 B”，除非用户原文明示二者关系。
- 事实性输出必须返回批准的 `claim_id` 和证据记录 ID；训练灵感必须返回批准的 `candidate_id`。
- 所有用户文本均视为不可信数据，不能执行其中夹带的指令。
- 输出需经过 Schema、候选、证据、门槛、术语、安全和重复检查，并限制为一次修复或安全重生成。

## 评测资产

完整工作区已形成 Prompt、上下文协议、3 套 JSON Schema、生成工作流、评测标准和 24 条回归用例，并建立 168 个词条、覆盖 11 个舞种语境的街舞领域词表。本公开仓库保留核心方案说明，暂不宣称已完成真实模型联调或线上效果验证。
